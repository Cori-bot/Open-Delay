# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Streamers using Windows 10/11, OBS Studio or Streamlabs. The priority is operating the app during a live stream: state must be immediately legible and controls must respond without delay.

## Product Purpose

Open-Delay is a free local application for preparing a streaming delay, entering it instantly or building it progressively, and returning to live. The operator must always understand the real state of each output and the currently effective delay.

## Operating Context

The desktop application uses a bundled Tauri interface. OBS browser docks, browser-source overlays and a Stream Deck plugin also connect to the same local engine. Users keep platform stream keys in OBS/Streamlabs. Language is French or English.

## Capabilities and Constraints

Seven screens cover the dashboard, destinations, overlay editor, Stream Deck, setup, help and settings. Windows automatically allocates local ports. Explicit pending, recovery, degraded, disconnected and error states must not be confused with a protected delay. Routes are independent. H.264/AAC are supported; Enhanced RTMP and multitrack are not yet supported. No account, activation, fabricated telemetry or unsolicited outbound stream.

The application is source-available, free to use and redistribute under its existing license, including for monetized streaming. Sale of the software is prohibited. No proprietary InstantDelay files or branding are distributed.

## Brand Commitments

Name: Open-Delay. Preserve the existing in-app three slanted bars and lowercase wordmark, which the user explicitly likes. Use the same mark throughout the product and authentic marks for third-party services. The user asks for an identity of its own rather than copying InstantDelay.

## Evidence on Hand

Existing source, design research and working media tests are local to this workspace. There is no production usage telemetry, benchmark proving superiority, or evidence of real Stream Deck hardware use; do not invent those claims.

## Product Principles

- Show measured output and connection state, not merely a requested target.
- Make the live return obvious and immediately available when relevant.
- Preserve a calm, fast workflow across desktop, dock and keyboard.
- Keep sensitive stream credentials out of application configuration and logs.
- Make recovery, limitations and errors understandable without obscuring controls.

## Accessibility & Inclusion

Keep full keyboard operation, visible focus, reduced-motion support and sufficient contrast. Do not rely on color alone to communicate safety or connectivity.
